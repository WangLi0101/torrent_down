# TorrNet Player — 磁力链接解析下载与边下边播播放器 实现文档

> 版本：v0.1（设计稿）
> 技术栈：Tauri 2.x + Rust + React + TypeScript + Tailwind CSS + Material Design 3

---

## 1. 项目概述

TorrNet Player 是一个桌面端（跨 Windows / macOS / Linux）磁力链接下载与播放应用：

1. 用户粘贴磁力链接，应用解析并自动获取种子元数据（文件列表、大小等）；
2. 用户选择要下载的文件（默认只勾选视频文件）；
3. 下载过程基于 BitTorrent 协议（DHT + Tracker + Peer Exchange）；
4. 视频文件支持**边下边播**：按顺序优先下载正在播放的分片，通过本地流媒体服务器向播放器按需提供字节流；
5. 界面遵循 Material Design 3（MD3）风格，使用 Tailwind CSS 实现。

### 1.1 核心能力清单

| 能力 | 说明 |
| --- | --- |
| 磁力链接解析 | 解析 `xt` / `dn` / `tr` / `xl` / `ws` 字段，校验 info-hash 合法性 |
| 磁力搜索 | 常用站点导航，使用独立原生 WebView 搜索；点击磁力链接返回添加任务流程 |
| 元数据获取 | DHT（BEP5）发现 Peer，通过 `ut_metadata`（BEP9）交换种子元数据 |
| 选择性下载 | 获取文件列表后按需勾选，未勾选文件不分配磁盘与带宽 |
| 顺序下载 | 引擎默认顺序下载（非 rarest-first），为边下边播服务 |
| 边下边播 | 本地 HTTP 流媒体服务器，支持 `Range` 请求（拖动进度条跳播） |
| 任务管理 | 列表 / 详情 / 暂停 / 恢复 / 删除（可选保留文件）/ 限速 |
| 断点续传 | 应用重启后恢复任务状态（Fastresume，无需重新校验） |
| 播放器 | 内置 HTML5 播放器，MD 风格控制条，播放进度与下载进度联动展示 |

### 1.2 非目标（本期不做）

- 做种 / 上传分享率管理（仅在下载期间按协议必要上传）
- `.torrent` 文件创建与发布
- 搜索结果抓取与跨站聚合（站点内搜索通过原生 WebView 完成）
- 字幕自动下载（预留播放器扩展点，后续版本加入）

## 2. 技术选型

| 层 | 技术 | 理由 |
| --- | --- | --- |
| 桌面框架 | Tauri 2.x | 体积小、Rust 后端与下载引擎同语言零开销集成 |

| 后端框架 | axum / tokio（librqbit 生态） | `librqbit::http_api::HttpApi` 基于 tokio，嵌入宿主进程 |
| 持久化 | SQLite（`rusqlite`） | 任务列表、文件选择状态、应用设置 |
| 前端框架 | React 18 + TypeScript + Vite | Tauri 官方推荐模板，生态成熟 |
| 样式 | Tailwind CSS v4 | 用 `@theme` 定义 MD3 design tokens |
| 主题风格 | Material Design 3（手工 tokens 实现） | 不引入重量级 MUI；按 MD3 规范自建色板 / 海拔 / 形状 / 状态层，风格可控且与 Tailwind 原生融合 |
| 播放器 | ArtPlayer（HTML5 封装） | 轻量、API 简洁、易做 MD 风格自定义皮肤 |
| 路由 | React Router v6 | 页面：首页 / 任务列表 / 播放 / 设置 |

> 备选说明：若团队偏好 Vue 3，前端层可等价替换（Vue 3 + Vite + Tailwind），IPC 与 Rust 层设计不变。

## 3. 总体架构

```
┌────────────────────────── Tauri 桌面进程 ──────────────────────────┐
│                                                                    │
│  ┌──────────── WebView (前端) ────────────┐   ┌── Rust 核心 ──┐   │
│  │ React + Tailwind + MD3 tokens           │   │               │   │
│  │                                        │   │  MagnetParser │   │
│  │  首页(输入磁力) ──┐                     │   │       │       │   │
│  │  任务列表        │ invoke / event       │   │       ▼       │   │
│  │  播放器页        │◄────────────────────►┼──►│  librqbit     │   │
│  │  设置页          │   Tauri IPC          │   │  Session      │   │
│  │                 │                       │   │  (DHT/Peers)  │   │
│  │  <video> ───────┼── HTTP(Range) ────────┼──►│  HttpApi      │   │
│  └─────────────────┘ http://127.0.0.1:port │   │  /stream/...  │   │
│                                            │   └───────┬───────┘   │
│                                            │           │           │
│                                            │     ┌─────▼─────┐    │
│                                            │     │  SQLite   │    │
│                                            │     │(任务/设置) │    │
│                                            │     └───────────┘    │
└────────────────────────────────────────────────────────────────────┘
                ▲                                   │
                │ 下载流量（TCP/uTP, UPnP 端口映射）  │ 元数据/分片交换
          DHT / Tracker / Peers
```

关键决策：

- **流媒体不走 Tauri 自定义协议，走本地回环 HTTP**。HTML5 `<video>` 对 `http://127.0.0.1` 的 `Range` 请求支持完善（seek 必需）；librqbit 的 stream 端点在读取字节区间时会**优先调度对应分片**，播放器拖动进度条后引擎立即转向下载目标区间的分片。
- 流服务器只绑定 `127.0.0.1`，端口在启动时随机分配并通过 IPC 告知前端，避免局域网暴露。

## 4. 核心技术方案

### 4.1 磁力链接解析

磁力 URI 规范（ Magnet URI ）关键字段：

| 参数 | 含义 | 处理 |
| --- | --- | --- |
| `xt` | `urn:btih:<info-hash>`（40 位 hex 或 32 位 base32） | 必填，校验并统一转为 40 位 hex 小写；同 hash 去重 |
| `dn` | 显示名称 | 元数据未取回前作为任务临时标题 |
| `tr` | Tracker 列表（可多个） | 传给引擎补充 Peer 来源 |
| `xl` | 总大小（字节） | 仅作展示 |
| `ws` | Web Seed URL | 可选透传 |

实现：直接使用 `librqbit::Magnet::parse()`，解析失败时返回结构化错误（`InvalidHash` / `MissingXt` 等）由前端提示。同时支持以下输入容错：

- 裸 40/60 位 info-hash（自动拼成磁力）
- 含磁力的整段文本（正则提取 `magnet:?...`）
- （后续版本）`.torrent` 文件路径

### 4.2 元数据获取（从磁力到文件列表）

磁力链接本身不含文件信息，流程如下：

```
磁力链接
  │  1. 解析出 info-hash + trackers
  ▼
启动 DHT（BEP5，自举节点 bootstrap）──────► 通过 info-hash 查询持有者
  │  2. 连接 Peer，握手
  ▼
BEP9 ut_metadata 扩展握手 ──► 分片拉取 metadata（种子字典）
  │  3. 校验 info-hash 与元数据 SHA1 一致
  ▼
得到文件列表：[{ 路径, 大小, 是否视频 }] ──► 前端展示勾选
```

以上全部由 librqbit 内置（`Session::add_magnet` 返回的 `ListOnly` 模式可**只拉元数据不开始下载**）。前端订阅 `task:metadata-resolved` 事件刷新文件选择页。

### 4.3 下载引擎

- **Session 单例**：应用启动时在 Rust 侧创建 `librqbit::Session`（含 DHT、UPnP 端口映射），生命周期与主进程一致。
- **顺序下载**：librqbit 的默认且唯一调度策略即顺序下载，天然契合边下边播（播放到哪下到哪）。对非播放状态的普通任务，同样按顺序下载，UI 提示"按顺序下载以支持即时播放"。
- **文件选择**：`AddTorrentOptions { only_files: Vec<usize>, output_folder, listed_only: true }`，未选中文件的分片优先级置 0。
- **边下边播时的分片联动**：播放器发起 `Range` 请求 → librqbit stream 端点读取区间 → 缺失分片被立即提权调度 → 读取端在分片就绪前挂起等待（不会返回空洞数据）。
- **暂停/恢复/删除**：通过 `ManagedTorrent` / `Api` facade 操作；删除时可选 `delete_files: bool`。
- **限速**：`Session` 支持 download/upload 限速，接入设置页。
- **Fastresume**：默认开启，重启应用后已下载内容无需重新哈希校验。

### 4.4 边下边播（本地流媒体服务器）

- 启动时在宿主进程内拉起 `librqbit::http_api::HttpApi`，绑定 `127.0.0.1:0`（随机端口）；
- 前端通过 IPC `get_stream_url(task_id, file_idx)` 获得播放地址：
  `http://127.0.0.1:{port}/torrents/{info_hash}/stream/{file_idx}`
- 端点行为：支持 `Range: bytes=a-b`，返回 `206 Partial Content` + `Content-Range` + 正确 `Content-Length`；`Content-Type` 按扩展名映射（mp4/mkv/webm…）；
- 播放器 seek → 新的 `Range` 请求 → 引擎优先下载目标区间分片 → 数据就绪后继续推流；
- 兜底策略：当分片等待超过阈值（如 15s），stream 返回 503，前端播放器显示缓冲 UI。

CSP 配置（tauri.conf.json）需允许媒体源：

```json
"csp": "default-src 'self'; media-src 'self' http://127.0.0.1:*; img-src 'self' data:; style-src 'self' 'unsafe-inline'"
```

> `<video>` 标签播放同源策略宽松（不设 `crossorigin` 即可直连），无需 CORS；如后续前端需 `fetch` 读取字节流，再为本地服务器加 CORS 头。

### 4.5 播放器

- 基于 ArtPlayer 挂载 `<video>`，视频源为 4.4 的 stream URL；
- 自定义 MD 风格控制层：播放/暂停、进度条（双层：**下载进度条 + 播放进度条**）、音量、倍速、全屏；
- 播放进度与任务进度联动：播放器 `timeupdate` 推算"已播区间是否已下载"，给用户"可以安心看 / 前方缓冲不足"的可视提示（缓冲水位条）；
- 进度条 hover 预览本期不做（预留 `preview` 插槽）。

### 5.3 页面与路由

| 路由 | 页面 | 内容 |
| --- | --- | --- |
| `/` | 首页 | 大号磁力输入框（filled text field）+ 剪贴板粘贴按钮 + 最近任务卡片 |
| `/task/new?magnet=…` | 添加向导 | ① 解析中（转圈）→ ② 元数据加载（文件列表勾选，视频默认全选，显示总大小/剩余）→ ③ 保存目录选择 → 确认添加 |
| `/tasks` | 任务列表 | 每行：缩略图标、名称、状态（连接中/下载/做种/暂停/出错）、进度条、速度、操作菜单（暂停/恢复/删除/播放） |
| `/tasks/:id` | 任务详情 | 文件清单（单文件进度）、分片图（piece map 热力图）、Tracker/Peer 统计 |
| `/player/:id/:fileIdx` | 播放页 | 全屏化播放器（ArtPlayer + MD 控制层），展示缓冲水位 |
| `/settings` | 设置 | 下载目录、默认勾选策略、速度限制、主题（亮/暗/跟随系统）、端口信息 |

### 5.4 关键交互流（添加任务）

```
用户粘贴磁力并回车
  → IPC: parse_magnet(text)            （纯解析，毫秒级）
  → 跳转 /task/new?magnet=…
  → IPC: add_task(listed_only=true)    （只拉元数据）
  ← 事件: task:metadata-resolved       （文件列表 + 视频识别结果）
  → 用户勾选文件、选目录
  → IPC: confirm_task(only_files, dir) （转为正式下载）
  → 跳转 /tasks，Snackbar 提示
```

## 6. Tauri IPC 设计

### 6.1 Commands（Rust → `#[tauri::command]`）

```ts
// types.ts（前端与 Rust 共享类型）
interface TorrentFileMeta { idx: number; path: string; size: number; isVideo: boolean }
type TaskState = 'FetchingMetadata' | 'Connecting' | 'Downloading' | 'Seeding' | 'Paused' | 'Error';
```

| 命令 | 入参 | 出参 | 说明 |
| --- | --- | --- | --- |
| `parse_magnet` | `text: string` | `{ infoHash, name?, trackers[], length? }` | 纯解析，容错裸 hash / 混合文本 |
| `add_task` | `magnet: string, listedOnly: true` | `{ taskId }` | 建任务（仅元数据），同名 hash 幂等 |
| `confirm_task` | `taskId, onlyFiles: number[], outputDir` | `void` | 开始正式下载 |
| `list_tasks` | — | `TaskSummary[]` | 全量任务概要（启动时/手动刷新） |
| `get_task_detail` | `taskId` | `TaskDetail` | 文件进度 / peers / trackers |
| `pause_task` / `resume_task` | `taskId` | `void` | |
| `remove_task` | `taskId, deleteFiles: bool` | `void` | |
| `get_stream_url` | `taskId, fileIdx` | `string` | `http://127.0.0.1:{port}/...` |
| `set_speed_limit` | `down?: number, up?: number` | `void` | 0 = 不限 |
| `get_settings` / `set_settings` | / `Settings` | `Settings` / `void` | 下载目录、主题、勾选策略等 |

### 6.2 Events（Rust → 前端推送，节流 500ms）

| 事件 | Payload | 触发时机 |
| --- | --- | --- |
| `task:metadata-resolved` | `{ taskId, name, files: TorrentFileMeta[], totalSize }` | 元数据就绪 |
| `task:progress` | `{ taskId, state, progress: f64, downSpeed, upSpeed, peers, eta, bufferedBytes?, pieceBitmap(压缩) }` | 状态/进度变化 |
| `task:error` | `{ taskId, code, message }` | 任务级错误 |
| `stream:buffer-wait` | `{ taskId, fileIdx, waitMs }` | 分片等待超阈值（前端显示缓冲提示） |

> 进度事件在 Rust 侧合并节流，避免高频 IPC 打满 WebView。

## 7. 数据模型（SQLite）

```sql
CREATE TABLE tasks (
  id            INTEGER PRIMARY KEY,
  info_hash     TEXT NOT NULL UNIQUE,
  name          TEXT,
  magnet_uri    TEXT NOT NULL,
  output_dir    TEXT NOT NULL,
  state         TEXT NOT NULL DEFAULT 'fetching',
  only_files    TEXT,               -- JSON array of file idx
  created_at    INTEGER NOT NULL,
  last_active   INTEGER
);

CREATE TABLE files (                -- 元数据解析后落库
  task_id       INTEGER REFERENCES tasks(id) ON DELETE CASCADE,
  file_idx      INTEGER NOT NULL,
  path          TEXT NOT NULL,
  size          INTEGER NOT NULL,
  is_video      INTEGER NOT NULL,   -- 后缀判断 + 可被 ffmpeg 探测修正
  PRIMARY KEY (task_id, file_idx)
);

CREATE TABLE settings (
  key TEXT PRIMARY KEY, value TEXT
);  -- 默认下载目录 / 主题 / 限速 / 自动勾选策略
```

- 应用启动：读 `tasks` 表，对 `state != error` 的任务调用 `Session::add_torrent` 恢复（Fastresume 免校验）；
- 视频识别：扩展名白名单（mp4/mkv/webm/avi/mov/flv/ts/m4v/wmv）+（可选）首次播放时用 ffprobe 校验容器有效性。

## 10. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 磁力无 Peer / 元数据拉不到 | 添加向导一直转圈 | 超时（默认 180s）+ 明确错误态 + 允许追加 tracker 重试 |
| 冷门资源分片慢，播放卡顿 | 体验差 | 缓冲水位 UI 提示 + 503 兜底 + 文档说明"资源健康度"决定体验 |
| mkv 等容器 moov/索引在文件尾 | HTML5 无法秒播 | 引擎顺序下载 + librqbit stream 会优先取头部关键区；实测仍卡则启用"首尾分片优先"补丁；必要时引导用 mp4 重封装资源 |
| WebView `<video>` 对部分编码不支持（如 HEVC 10bit） | 有声无画 / 无法播放 | 播放前能力检测；后续版本可接 `ffmpegsidecar` 转码或系统播放器外呼 |
| 端口被占用 / 防火墙弹窗 | 流服务起不来 | `127.0.0.1:0` 随机端口天然规避；UPnP 映射失败仅影响外连，静默降级 |
| Windows 删除占用文件失败 | 删除任务报错 | 提示"文件被占用"，保留 DB 记录供重试 |
| 第三方站点内容与可用性 | 站点内容和访问状态由第三方控制 | 提供站点导航与独立 WebView；用户可切换站点，搜索结果由原站点展示 |

## 12. 磁力搜索（已实现）

- 入口：首页的“还没有磁力链接？”以及桌面侧栏、移动端底栏的“搜索”，路由为 `/search`。
- 内置站点：SkrBT（`https://skrbtso.top/`）、BT4G（`https://bt4gprx.com/`）、Bitsearch（`https://bitsearch.eu/`）。站点清单统一维护于 `src/data/search-sites.json`，Rust 使用 `include_str!` 读取同一份清单；修改后需要重新构建桌面应用。
- 主窗口调用 `open_search_site({ siteId })` 打开独立原生 WebView。同一站点复用现有窗口并保留当前页面；关闭后可重新打开。
- 普通新窗口链接在当前搜索窗口打开；支持 `Alt + ← / →` 后退 / 前进，`Ctrl / ⌘ + R` 刷新。
- Rust 拦截 `magnet:` 导航和新窗口请求，复用现有解析器校验链接；通过定向事件 `search:magnet` 回传主窗口并聚焦，前端进入现有文件选择流程。无效链接通过 `search:error` 显示错误，不创建下载任务。
- 搜索页面也提供磁力链接 / info-hash 输入框，以及各站点地址的复制按钮。
- 搜索窗口使用远程页面，不授予主窗口的 Tauri 能力；禁止导航到本地应用地址及非 HTTP(S) 协议（磁力链接单独处理）。
- 浏览器预览展示导航页面并禁用 WebView 按钮；实际站点访问需在 Tauri 桌面应用中验证，网络或站点不可用时可切换站点。
